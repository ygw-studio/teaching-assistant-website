# 知序教辅网站同学接手开发交接说明

这份文档给继续开发的同学使用。目标是让对方能快速跑起来、看懂项目结构、知道当前能用什么、接下来该改哪里。

## 1. 项目定位

知序是一个面向高校 Python 教学场景的教学辅助网站，当前是前后端分离原型，已经具备学生、教师、管理员三个身份。

当前核心模块：

- 学生端：课程学习、知识点小测、在线 Python 练习、实验指导、AI 助教、个人主页。
- 教师端：课程章节和知识点管理、实验指导管理、学生记录展示入口。
- 管理员端：账号管理、角色权限入口、系统设置入口。
- 后端：登录鉴权、角色权限、课程数据、实验指导、Python 代码运行、AI 助教接口、行为记录基础。

## 2. 技术栈

- 前端：React + Vite + Lucide React
- 后端：FastAPI + SQLite
- 在线 Python：开发阶段默认调用服务器本机 Python；正式上线建议切到 Docker 沙箱
- AI 助教：后端统一保存 API Key，前端只请求本项目后端接口

## 6. 环境变量和密钥

不要把 `backend/.env` 直接发到群里或提交到公开仓库，因为里面可能包含 AI API Key、数据库路径、管理员初始化密码等敏感信息。

交接时推荐做法：

- 代码通过 Git 私有仓库或压缩包交接。
- `.env` 单独私发，或让同学根据 `.env.example` 自己配置。
- AI API Key 只放后端，不写进前端代码。
- 如果要给真实数据库，先确认里面没有学生隐私数据。

后端常见配置项：

```env
DATABASE_PATH=E:\codex\教辅网站开发\backend\data\teaching-platform.db
AI_API_URL=https://xxx/chat/completions
AI_API_KEY=sk-xxx
AI_MODEL=xxx
CODE_EXECUTION_MODE=local
```

## 8. 继续开发建议

优先级从高到低：

1. 账号管理完善：手机号唯一绑定、批量导入、重置密码、禁用账号。
2. 教师端完善：课程章节、知识点、小测题、实验指导都由教师增删改查。
3. 学生端完善：学习进度、小测完成状态、代码运行记录要写入后端。
4. AI 助教完善：接入正式中文大模型，保存对话内容、时间、账号和上下文。
5. Python 运行安全：校内上线建议使用 Docker 沙箱，不要直接在服务器裸跑学生代码。
6. 部署上线：服务器、反向代理、HTTPS、数据库备份、日志监控。

## 9. 交接给同学的推荐流程

最稳的方式：

1. 建一个 GitHub/Gitee 私有仓库。
2. 把项目代码提交上去，但不要提交 `.env` 和真实数据库敏感数据。
3. 把这份文档发给同学。
4. 同学按文档启动前端和后端。
5. 用三个测试账号登录走一遍功能。
6. 约定任务分工，例如一个人做教师端内容管理，一个人做学生端学习记录。
7. 每次改动前先拉取最新代码，改完后写清楚提交说明。

如果暂时不用 Git，也可以压缩整个项目发给同学，但这种方式后续合并代码会比较麻烦，不适合多人长期开发。

## 10. 当前需要特别注意的点

- 前端不是纯静态摆设，已经会请求后端接口。
- 管理员首页数据应从真实接口读取，不要再写假的大数字。
- Python 当前运行在后端所在机器上；本地开发就是你的电脑，学校内网上线就是学校服务器。
- 正式开放给学生前，Python 代码运行必须考虑沙箱隔离。
- AI 助教的 API Key 只能放后端，不能暴露到浏览器。
- 数据库现在用 SQLite，适合初期试运行；人数明显变多后可迁移到 PostgreSQL/MySQL。
